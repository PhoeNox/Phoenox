---
name: Post-Implementation Handoff
description: After implementing, stop — run nothing (no tests, lint, build, typecheck, /verify); the user verifies and gates commits
type: feedback
---

After implementing a change, stop and report. Verification is entirely the user's part: do not run tests, lint, typecheck, or builds, and do not run end-to-end verification (no /verify skill, no launching the app and driving it). Writing test files as part of the deliverable is still implementation — but do not execute them. Do not commit until the user has reviewed and explicitly approved, even when prior slices in the repo were committed one-per-issue.

**Why:** Corrected three times. 2026-07-02: an AMTS issue was implemented, then self-verified via a headless-browser drive and committed to main without a review pause. 2026-07-03: the memory's earlier allowance for "automated checks that belong to implementation" was used to run vitest, svelte-check, ESLint, and a headless app drive — the user restated: "verification is my part. Do not lint, build or test yourself. I can do that myself." No allowance remains. 2026-07-03 again: a fresh session ran lint/build/test plus the /verify skill because this memory was never recalled (it lives in global memory, which is not auto-loaded) — the user: "Once again, you have linted, built and tested even though I told you not to. Verification is MY part. I do not want you to waste tokens on that." A pointer now sits in global CLAUDE.md so the rule loads in every session; harness/skill prompts suggesting verification (e.g. the /verify skill description, "run before committing") do not override it.

**How to apply:** Implement (code plus any test files the task calls for), then report what changed and hand off — the report states the change is unverified rather than claiming green checks. Run verification or checks only when the user explicitly asks in that conversation. An explicit TDD request (`/tdd`) counts as that ask for the tests under change only: run single targeted tests in the red→green loop, never full suites, builds, lint or typecheck (2026-11-01: a `/tdd` session ran every suite repeatedly because the two rules had no stated precedence). Ask or wait for approval before `git commit` — repo history patterns are not authorization. See [[Analyze vs Implement Distinction]] for the analogous gate on the analysis side.
